Upload planning injects a shape-only encoder to execute the actual source
upload helper without large allocations. It does not prove numerical resize
or pixel parity. The separate real PNG comes from the actual conversion helper.
Canonical callers must produce those source PNG/2048²/Lanczos/disabled semantics
and preserve omitted MIME across storage creation and signed PUT. The checked
common DTO now supports optional MIME; native/guest binding is independent.
Missing upload owner returns typed HostFailure, with no fabricated empty MIME.

Source flattens batches in input order and uploads the first eight frames per
helper call. Single-image and texture helpers upload extra frames even though
the node selects only the first resulting URL. Multi-image autogrow schema has
2–4 sockets, but execute forwards dictionary values and the helper flattens all
batches. Input images use an ordered vector to preserve that order. Optional
texture uploads occur before base image uploads. Empty first-URL groups fail
at their source position. Prepared groups retain source frame roles/indices,
dimensions, total pixel budgets, encoded PNG and declared MIME separately.
The actual canonical owner verifies storage-create/signed-PUT completions in
retained prompt/attempt/execution-node/plan scope. Receipt bytes are selectors,
never grants. Distinct handles and bounded receipts must share one invocation.

Text prompt validation strips only for checking length; its Pydantic model
also restricts raw prompt to 600. Refine checks stripped texture length while
its API model has no raw maximum. Image/multi texture prompt models restrict
raw length. Texture's execute/model has no 600-character limit despite its
widget tooltip. Original request strings remain intact; pose strings lower
case, seeds forward, nullable fields omit, and explicit false controls remain.
Pydantic polygon validation can occur after uploads. Oracles and regressions
preserve that ordering rather than moving every error into preflight.

GLB downloads and authorized compatibility saves precede FBX requests/saves.
`MeshyFileOwner::complete_download` receives exact bytes, filename, task ID,
URL, handle and terminal receipt immediately after each download. It must
retain real caller-owned File3D resources and perform the checked compatibility
save; default is typed HostFailure. No leaf parser or filesystem owner is
invented. Actual source File3D preserves opaque bytes and rewinds the stream;
the fixture's minimal GLB and opaque FBX probe establish byte semantics, not
native mesh parser conformance. The actual source helper leaves the GLB saved
if the second download fails. Native save/cleanup policy remains an explicit
owner gate; zero output publication does not imply zero filesystem residue.
